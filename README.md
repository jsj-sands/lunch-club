## 2026-10-20 추가 · 관리자 없이 Slackbot 알림 받기 (우선 추천)

**관리자 권한 없이 가능한 더 간단한 방법**을 추가했습니다. 각 직원이 Slack 개인 설정에서 'Slack으로 이메일 가져오기 → 전달 주소 가져오기'로 고유 이메일 주소를 발급받고, 그 주소를 기존 Google Apps Script의 스크립트 속성에 저장합니다. 점심 초대/참여 요청 등 발생 시 `MailApp.sendEmail`이 해당 Slackbot 주소로 메일을 발송하므로, 수신자는 Slackbot 대화에서 확인할 수 있습니다. Gmail 공유 드라이브 알림보다 파일이 쌓이지 않고, Apps Script의 실행 계정 본인에게도 사용할 수 있습니다.

- 스크립트 속성 `LUNCH_SLACKBOT_FORWARD_EMAILS`: 예를 들어 `{"juri":"여기에_손주리의_Slackbot_전달_주소"}` 처럼 직원 내부 ID별 전달 주소를 JSON 문자열로 저장합니다. 실제 전달 주소는 **GitHub에 절대 공개하지 않습니다**.
- 스크립트 속성 `LUNCH_SLACKBOT_TEST_MEMBER`: 한 명의 내부 ID(`juri` 등)를 입력하고 편집기 함수 `testLunchSlackbotForwarding`을 직접 실행해 Slackbot 수신을 확인합니다. Google 메일 발송 권한을 승인해야 할 수 있습니다.
- **발송 우선순위:** Slackbot 이메일 → Google Drive 공유 파일 → 기존 Slack Bot API. 설정된 통로만 사용하며 동일 알림의 중복 발송을 피합니다. 외부 알림이 모두 실패해도 모임/승인 기록과 웹앱 알림은 그대로 유지됩니다.
- **한계:** 회사가 Slack 수신 이메일을 금지했거나 전달 주소를 쓰지 않으면 알림을 받을 수 없습니다. Google의 메일 발송 한도와 지연에 영향을 받습니다. 실제 Slack 도착 여부를 서버에서 확정할 수 없습니다.

자세한 직원용 설정 가이드는 `Slackbot_이메일_알림_설정_안내.txt`입니다. [Slack 공식 문서](https://slack.com/intl/ko-kr/help/articles/206819278-Slack%EC%97%90-%EC%9D%B4%EB%A9%94%EC%9D%BC-%EB%B3%B4%EB%82%B4%EA%B8%B0) 및 [Google MailApp 문서](https://developers.google.com/apps-script/reference/mail/mail-app)를 참고했습니다.

## 2026-10-20 업데이트 · Google Drive 파일 공유로 Slack 알림 우회 (선택)

**Slack 관리자가 아니어도 시험할 수 있는 대안**입니다. 기존 Apps Script에서 새 Google Drive 텍스트 파일을 만들고 특정 동료에게 읽기 권한을 공유합니다. 이미 회사 Slack에서 Google Drive 앱 알림을 받는 동료라면 공유 알림이 Slack으로 올 수 있습니다. 다만 알림 앱 설정과 회사 정책에 따라 다르므로 실제 직원에게 **테스트가 필수**입니다. 참고: [Slack 공식 설명](https://slack.com/intl/ko-kr/help/articles/205875058-Slack%EC%9A%A9-Google-Drive), [Drive API permissions.create](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/create).

- **설정:** 기존 Google Apps Script > 프로젝트 설정 > 스크립트 속성에 `LUNCH_DRIVE_MEMBER_EMAILS` JSON 추가. 예: `{"juri":"동료의_실제_구글이메일"}` (문자열은 정확한 이메일 주소로 변경). 해당 이메일/직원 매핑은 GitHub에는 올리지 않습니다.
- **선택:** `LUNCH_DRIVE_ALLOWED_DOMAIN`에 정확한 회사 도메인을 넣으면 외부 계정으로의 잘못된 공유를 막을 수 있습니다.
- **시험:** `LUNCH_DRIVE_TEST_MEMBER`를 `juri`처럼 등록하고 Apps Script의 `testLunchDriveNotification` 함수를 수동 실행합니다. 상대방이 실제로 Slack Drive 알림을 받았는지 확인합니다.
- **이벤트:** 초대, 참여 요청, 수락, 거절, 승인, 참여 요청 취소. 이벤트마다 전용 폴더에 새 파일을 만들어 공유합니다. 성공한 신규 공유는 기존 Slack 봇을 통한 중복 발송을 피합니다.
- **안전:** 알림 실패가 모임·선택 저장을 취소하지 않습니다. 공유 알림은 Google Drive 계정의 스팸/알림 정책에 영향을 받습니다. 파일은 14일 후 정리합니다. 부서/이름만으로 메일 주소를 추측하지 않습니다.
- **중요한 예외:** Apps Script **소유자 본인에게는 자기 파일을 새로 공유할 수 없기 때문에** 이 경로의 Slack 알림이 불가능합니다. 소유자도 웹앱 내 초대/요청 알림은 정상 확인할 수 있습니다. 필요하다면 별도의 중립 Google 발신 계정 또는 정식 Slack 연동이 필요합니다.

자세한 단계와 실제 직원용 빈 JSON 예시는 `Google_Drive_Slack_알림_설정_안내.txt`에 있습니다. **별도 Slack 앱을 새로 설치하는 기능이 아닙니다.** 기존 Slack 앱에서 Google Drive 공유를 알릴 수 있는 환경을 재사용합니다.

## 2026-10-20 최신 수정 · 기존 따로 먹기 모임 참여 요청 + 알림

기존 디자인, 일반 점심(메가존/런치타임), 대표님 점심, 다인원 따로 먹기, 식당 등록을 보존한 채 다음을 추가했습니다.

1. **기존 모임에 참여 요청**: 따로 먹는 모임 카드에서 **이 모임에 참여 요청**을 누르면 해당 날짜의 최초 생성자에게 요청이 전달됩니다. 별도 초대를 기다릴 필요가 없습니다.
2. **생성자의 승인/거절**: 만든 사람의 **오늘 점심, 어떻게 할까요?** 아래에 미처리 요청이 나타납니다. 승인이 필요하며, 다른 모임 멤버는 대신 승인할 수 없습니다.
3. **초대받은 직원 알림**: 기존 동료 초대에도 초대된 사람의 선택 패널에 수락/거절 알림이 나타납니다. 페이지를 열어 둔 상태에서는 팀 공유 내용을 약 30초마다 갱신합니다.
4. **참석 상태 자동 정리**: 직접 초대를 수락하거나 참여 요청이 승인되면 자동으로 **함께 점심에서 제외**되어 모임에 나타납니다. 초대 대기/참여 요청 대기/거절 시에는 기존 상태가 바뀌지 않습니다.
5. **Slack DM (선택)**: 팀에서 Slack App을 만들고 Apps Script의 스크립트 속성에 봇 토큰과 직원 Slack ID를 등록하면, 초대·참여 요청·수락/승인/거절 시 **받아야 할 사람에게 DM**을 보냅니다. 비밀 키를 GitHub에 저장하지 않습니다. Slack 설정이 없어도 앱 내 알림은 작동합니다.
6. **Slack 링크로 날짜 바로 열기**: DM에는 해당 날짜를 미리 선택한 점심판 주소가 포함됩니다. 클릭한 사람은 사이트에서 각자 자신의 이름을 선택하여 승인·수락합니다.

### 직원별 Slack DM 연동 방법 (관리자가 한 번만)

1. Slack 관리자에게 사내 앱 설치가 가능한지 확인합니다. <https://api.slack.com/apps>에서 **Create an App → From scratch**로 `SANDS Lunch Club` 봇을 만듭니다.
2. **OAuth & Permissions → Bot Token Scopes**에 `chat:write`와 `im:write`를 추가합니다. **Install to Workspace** 후 `Bot User OAuth Token`을 받습니다. 토큰은 `xoxb-...` 형식입니다.
3. Slack에서 직원 프로필의 **멤버 ID 복사**를 사용해 각 직원의 Slack ID(`U...` 또는 `W...`)를 확인합니다.
4. 기존 Google Apps Script 편집기에서 **프로젝트 설정(톱니) → 스크립트 속성**에 다음 두 속성을 추가합니다. 팀 키나 직원 ID를 GitHub 화면 파일에 기입하지 마세요.

   - `LUNCH_SLACK_BOT_TOKEN`: `xoxb-...` (봇 OAuth 토큰)
   - `LUNCH_SLACK_MEMBER_IDS`: 예: `{"seongjun":"U1234567890","juri":"U2234567890","hyunsu":"U3234567890"}`

5. Slack ID를 등록한 사람만 DM을 받을 수 있습니다. 목록의 직원별 내부 ID는 `core.js` 앞쪽 `MEMBERS` 배열과 같습니다. 전체 직원 설정 예시는 동봉 `Slack_알림_설정_안내.txt`를 확인해 주세요.
6. 위의 Script Properties는 Google 서버에만 보관합니다. 기존 `Code.gs`를 이번 ZIP의 설정 화면에서 복사해 업그레이드하고 **배포 관리 → 새 버전 → 배포** 후 실제로 초대·요청을 보내 확인합니다.
7. Slack 알림 실패가 있더라도 앱 데이터는 저장되고 웹앱 알림은 유지됩니다. **Slack 전송을 별도로 재시도하지 않으므로** 메시지를 못 받으면 사이트에서 상태를 확인해야 합니다. 앱 내 실시간 웹 푸시, Slack 메시지의 인터랙티브 승인 버튼은 포함하지 않았습니다.

**보안:** 현재 사이트는 직원 이름 선택 + 팀 키 공유 방식이며 직원별 로그인을 검증하지 않습니다. 팀 키를 아는 사용자는 다른 직원의 이름으로 동작할 수 있으므로 승인·초대 권한은 사내 신뢰를 전제로 합니다. Slack DM도 강한 신원 확인 수단으로 해석하면 안 됩니다.

## 기존 수정 · 일반 점심과 대표님 점심 분리

- **일반 점심**은 개인별로 **메가존 또는 런치타임 중 택 1**입니다. 참여자는 `함께 먹기`를 누른 뒤 응답 패널이나 해당 식단 카드에서 식당을 선택합니다. 다른 곳을 누르면 변경됩니다. 오른쪽 패널에 두 곳의 인원과 이름이 집계됩니다. 별도의 전체 점심 장소 확정은 필요하지 않습니다.
- **대표님과 점심**인 멤버는 `과천 맛집 골라보기`의 33곳 중 하나를 선택하고 **대표님 점심 장소로 확정**을 누릅니다. 해당 날짜의 대표님 점심 장소 하나가 팀 공유 서버에 저장되어 모든 참석자에게 표시됩니다. 다른 식당으로 변경 시 확인 창이 뜨며, 참석자는 확정 취소도 가능합니다.
- 대표님 점심 장소의 시간은 팀 설정의 **기본 만남 시간(기본 12:00)** 을 사용합니다. **웹앱의 장소 확정은 실제 식당 예약이 아닙니다.** 영업 여부·예약은 네이버 지도·전화로 별도 확인합니다.
- 대표님 일정 취소·불참·따로 먹기·가져온 식단 사진·이전 투표 기록은 보존합니다. 이전 버전의 추가 식당/전체 장소 확정 기록은 백업 형태로 보관하지만, 더 이상 일반 점심 투표에 포함되지 않습니다.

- 이전 메뉴 표시 수정 자체에는 공유 서버 재배포가 필요하지 않았지만 **이번 2026-10-20 대표님 점심·다인원 따로 먹기 장소 공유는 서버 업데이트가 필수**입니다. 원문 링크는 그대로 제공합니다.

## 포함된 이전 수정 · 식단 사진·반찬과 이미지 삭제

기존 CI·글꼴·참석 선택·런치타임 자동 조회까지 포함한 통합 파일입니다. 이번 업데이트에서는 다인원 따로 먹기와 모임별 식당 저장을 위해 기존 Google 공유 서버 코드를 반드시 새 버전으로 갱신합니다.

### 메가존 사진과 함께 나오는 메뉴

- **오늘 식단**에 메뉴별 음식 사진, 메인 메뉴명, 밥·국·반찬 등 전체 구성을 표시합니다. 메인과 같은 이름은 아래 목록에서 중복 표시하지 않습니다.
- **사진을 누르면 확대**해서 볼 수 있고, 확대 화면에서도 함께 나오는 메뉴를 확인합니다. 식판 전체가 보이도록 사진을 자르지 않습니다.
- **이번 주 식단**은 기존 메뉴 요약을 유지합니다. 날짜별 **사진·반찬 보기**를 펼치면 해당 날짜의 상세 카드가 나옵니다. 날짜를 누르면 그날의 점심판으로 이동합니다.
- PC에서는 카드로 나란히, 좁은 화면에서는 작은 사진과 메뉴명 아래에 반찬을 줄바꿈해 배치합니다.
- [Welplan 공개 API](https://welplan.pmh.codes/docs/api)의 같은 응답에 사진과 전체 구성이 있어 별도 상세 조회 요청을 추가하지 않았습니다. 제공된 사진 주소를 직접 표시하며 고정 메뉴 사진을 파일에 복사해 두지 않습니다.
- 사진·반찬 정보가 없는 코스나 사진 로드 오류가 있어도 메인 메뉴와 참석 선택은 사용할 수 있습니다. 원문 링크도 유지합니다.
- 브라우저의 식단 캐시를 v2로 갱신해 이전의 메인 이름만 있는 결과가 새 표시를 막지 않도록 했습니다.

### 동료가 올린 식단 이미지 삭제

1. 내 이름을 선택합니다.
2. 런치타임 아래 **올린 이미지 삭제**를 누릅니다. **올린 이미지 교체** 옆에 있습니다.
3. 삭제할 **하루 또는 주간의 적용 기간**을 확인합니다.
4. **하루 이미지 삭제** 또는 **주간 이미지 삭제**를 누르면 삭제합니다. **유지하기**를 누르면 그대로 둡니다.

- 팀 공유 상태에서 삭제하면 동료들의 점심판에도 반영됩니다. 다른 화면은 다음 공유 확인 때 갱신됩니다(화면이 열려 있는 동안 약 30초 간격).
- 공유 전의 기기 내 이미지도 삭제할 수 있습니다. 이 경우 해당 브라우저의 이미지 저장소만 바뀝니다.
- **카카오에서 자동으로 가져오는 프로필 사진은 계속 표시됩니다.** 삭제 버튼은 직접 올린 이미지에 적용됩니다.
- 하루용·주간용이 모두 있으면 현재 표시되는 하루용이 먼저 삭제 대상입니다. 하루용을 삭제한 뒤에는 기존 주간 이미지가 표시되며, 확인 화면에 이를 미리 안내합니다.
- 다른 멤버가 먼저 이미지를 교체했으면 새 이미지가 삭제되지 않도록 중단하고 다시 확인하도록 안내합니다. 로컬 삭제도 최신 저장 정보를 다시 읽어 다른 탭에서 교체·추가한 사진을 보존합니다.
- 공유 서버의 삭제 확인을 받아야 완료로 표시합니다. 삭제 도중 통신이나 저장에 실패하면 오류를 표시합니다.
- 서버는 확인한 식단 파일 하나를 전용 Drive 폴더에서 휴지통으로 이동하고 해당 식단의 연결 정보를 지웁니다. 다른 날짜·범위의 업로드 파일을 함께 삭제하지 않습니다.
- 예전 공유 서버에서는 삭제를 실행하지 않고 업데이트 안내를 표시합니다. 기존 참석·식단 조회는 이어서 사용할 수 있습니다.

## 포함된 이전 수정 · 런치타임 식단 자동 조회

카카오 프로필 사진을 매일 저장하지 않아도 점심판에서 볼 수 있도록 연결했습니다. 첨부 QR은 이미 사용하던 [런치타임 카카오 채널](https://pf.kakao.com/_xbbMPn)로 연결됩니다. QR을 매일 다시 읽는 과정은 필요 없습니다.

- 공유 연결 후 점심판을 열면 현재 공개된 프로필 사진을 조회합니다. 직원 이름을 고르기 전에도 식단을 볼 수 있습니다.
- 화면이 열려 있는 동안 약 5분마다 다시 확인합니다. 다른 화면에 갔다가 돌아왔을 때도 마지막 조회로부터 5분이 지났으면 확인합니다.
- **사진 다시 불러오기** 또는 **식단 새로고침**으로 직접 재조회할 수 있습니다. 요청이 겹치지 않도록 처리하며, 서버는 일반 요청에 5분, 직접 새로고침에 최소 1분 캐시를 적용합니다.
- 사진을 누르면 크게 볼 수 있습니다. **마지막 확인 시각**을 한국 시간으로 표시합니다.
- 자동 사진에는 식단 날짜 정보가 없으므로 조회 날짜를 메뉴 날짜로 기록하지 않습니다. 이미지에 적힌 날짜를 확인해야 합니다. 식당에서 아직 사진을 바꾸지 않았다면 전날 식단일 수 있습니다.
- 오늘 화면에는 자동 사진을 보여 줍니다. 내일·모레·과거 날짜에는 **선택한 날짜의 식단이 아니에요**라고 안내하고, 현재 카카오 사진은 별도의 보기 버튼으로 엽니다.
- 기존에 직접 올린 하루·주간 이미지는 **동료가 올린 식단**에서 펼쳐 봅니다. 다른 날짜를 보거나 자동 조회가 실패한 경우에는 해당 날짜의 업로드 이미지를 펼쳐 표시합니다. 하루용이 주간용보다 우선입니다.
- 조회가 실패하면 이전에 가져온 사진과 원래 확인 시각을 유지하며 재조회 실패를 알립니다. 사진 파일 자체가 열리지 않을 때도 원문 링크와 직접 업로드를 사용할 수 있습니다. 식단 오류는 참석 선택·초대 저장을 막지 않습니다.

**자동 실행 범위:** 이번 파일은 **점심판을 열 때 + 열어 둔 동안 주기적으로 조회**하는 방식입니다. 페이지를 닫아 둔 상태에서 오전 9시에 실행하는 예약 작업은 설치하지 않습니다. 식당이 오전 9시 이후에 사진을 바꿔도 사이트를 사용하는 동안 다시 가져오도록 구성했습니다.

**연결 방식:** 공개 카카오 채널의 프로필 정보는 로그인 없이 서버에서 읽을 수 있습니다. 브라우저에서 다른 사이트를 직접 읽는 요청은 정상 메타데이터를 반환하지 않아, 기존 Google 공유 서버가 공개 프로필 정보를 읽고 사진 주소만 전달합니다. 다른 사람의 카카오 계정이나 친구 목록에 접근하지 않습니다. 자동 조회의 공개 사진은 카카오 CDN에서 표시하며, 업로드용 Drive 폴더에 복사하지 않습니다.

2026-10-19에 실제 공개 응답과 900×1300 프로필 사진을 확인했습니다. 카카오가 제공하는 화면용 데이터 형식이 바뀌거나 접근이 제한되면 자동 조회 코드 조정이 필요할 수 있습니다. 원문 링크와 직접 업로드는 계속 보조 수단으로 제공됩니다.

## 포함된 이전 수정 · 참석 선택과 따로 먹기

### 눈에 보이는 내 점심 선택

현황 위에 **오늘 점심, 어떻게 할까요?** 패널을 넣었습니다. **나는 → 내 이름**을 고른 뒤 큰 버튼 **함께 먹기 · 따로 먹기 · 안 먹기**를 누릅니다. 이름을 눌러야만 선택창을 찾을 수 있었던 기존 경로도 보조 기능으로 남아 있습니다.

| 현황 | 들어가는 사람 |
| --- | --- |
| 함께 점심 · 초록색 | 직접 **함께 먹기**를 선택한 사람 |
| 대표님과 점심 | 그날의 기본 대표님 일정이 있거나 직접 대표님과 먹기를 선택한 사람 |
| 오늘 안 먹음 | 직접 **안 먹기**를 선택한 사람 |
| 미선택 | 아직 응답하지 않았거나 선택·개인 대표님 일정을 취소한 사람 |
| 따로 먹는 점심 | 동료와 따로 먹거나 개별 식사를 선택한 사람. 모임 카드를 별도로 표시 |

- 대표님 기본 일정 외에는 **미선택**으로 시작합니다. 주말도 같습니다. 날짜가 바뀔 때 전날의 선택이 자동으로 이어지지 않습니다.
- 직접 함께 먹기를 선택한 사람만 일반 점심 장소(메가존/런치타임) 집계에 포함됩니다. 대표님 점심 장소 확정은 대표님과 점심 참석자만 할 수 있습니다.
- **안 먹기** 사유에 **연차·반차·외근·출장**을 하나의 항목으로 추가했습니다. 사유는 선택사항이며 기존 사유와 직접 입력도 사용할 수 있습니다.
- **선택 취소 · 미선택으로**를 누르면 내 선택을 해제할 수 있습니다.
- 한 번에 하루만 봅니다. **← / →**, 날짜 입력, **오늘** 버튼을 유지했습니다. 선택과 모임은 화면에 표시한 날짜에 저장됩니다.
- 네 현황 그룹은 PC에서 2×2, 모바일에서 한 열로 배치합니다. 팀명은 한 번만 표시하고 이름은 줄바꿈합니다. 팀명 가나다순 → 이름 가나다순으로 정렬합니다.

### 대표님 점심 취소

- 내 상태가 대표님과 점심이면 선택 패널에 **내 대표님 점심 취소** 버튼이 나타납니다. 누르면 **나만 미선택**으로 이동합니다. 이후 함께 먹기·따로 먹기·안 먹기를 직접 고릅니다.
- 그날의 전체 일정이 취소되었으면 별도의 **오늘 대표님 점심 전체 취소** 체크를 사용합니다. 자동 기본 일정에 해당하는 사람들이 미선택으로 이동합니다. 개인이 직접 선택한 참석·불참·대표님 일정·따로 먹기는 유지됩니다.
- 전체 취소를 해제하면 자동 기본 일정이 돌아옵니다. 개인적으로 취소했던 상태는 유지됩니다. 개인 일정 복원은 선택 패널의 **내 기본 대표님 일정 복원** 또는 내 이름의 상세 선택창에서 할 수 있습니다.
- 취소 후 자동으로 함께 먹는 인원에 들어가지 않습니다.

### 여러 명이 따로 먹는 모임

예를 들어 손주리·윤현수·천진기 세 명이 따로 먹을 때:

1. 손주리가 본인 이름을 선택하고 **따로 먹기**를 누릅니다.
2. 체크박스에서 **윤현수와 천진기를 동시에 선택**하고 **선택한 동료 초대하기**를 누릅니다.
3. 손주리는 따로 먹는 인원으로 이동하며, 윤현수와 천진기의 기존 점심 상태는 그대로 유지됩니다.
4. 두 동료가 각각 본인 이름으로 **수락하고 따로 먹기**를 누르면 3명 모임으로 표시됩니다.
5. 세 명 중 누구든 아래 **과천 맛집 골라보기 → 따로 먹기 장소**에서 식당을 등록하면 같은 모임 참석자에게 표시됩니다. 다른 모임이나 대표님 점심 장소는 바뀌지 않습니다.

초대는 이 점심판 안에 표시됩니다. 동료의 기기에서도 보려면 같은 팀 공유 연결을 사용해야 합니다. 선택 결과와 초대는 화면이 열려 있는 동안 약 30초마다 확인합니다.

- 혼자 먹는 경우에는 **동료 지정 없이 따로 먹기**를 사용합니다.
- 대기 중인 초대를 포함해 한 사람은 한 모임에만 속할 수 있습니다. 모임을 만든 사람은 **동료 추가 초대**를 눌러 인원을 늘릴 수 있습니다.
- 대기 중 초대는 보낸 사람이 취소하거나 받은 사람이 거절할 수 있습니다. 초대한 사람은 따로 먹기로 남습니다.
- 수락한 모임에서 **모임 나가기 · 미선택으로**를 누르면 본인만 미선택이 됩니다. 모임을 만든 사람이 나가면 초대 연결이 해제되고 나머지 수락자는 각자 따로 먹는 상태를 유지합니다. 모임 식당 기록은 해제됩니다.
- 참석 상태를 새로 고르면 본인이 속한 초대·모임도 정리됩니다. 다른 사람의 개인 선택은 유지됩니다.

## 공유와 파일 구성

기존 Google Apps Script 연결을 사용합니다. 선택·초대는 Script Properties, 식단 이미지는 초기 실행 때 만든 전용 비공개 Drive 폴더에 보관합니다. 주기적인 조회는 이미지 정보만 전송하고 파일은 필요할 때 가져옵니다. 서버 잠금과 변경별 확인 응답을 통해 동시 변경을 처리하며, 저장 확인을 받아야 성공을 표시합니다.

팀 키가 맞는 요청만 처리하는 소규모 팀 공유판입니다. 초대 링크를 가진 사람은 멤버 이름을 선택해 기록을 수정할 수 있습니다. 실제 팀 키·팀 키를 넣은 서버 코드·초대 링크는 공개 저장소에 올리지 마세요. 배포용 기본 소스에는 실제 팀 키가 없습니다.

공유 기록과 전용 이미지는 최근 90일 기준으로 정리합니다. 로컬 점심 기록은 최근 120일을 보관합니다. 서로 다른 기기에서 자동으로 같은 결과를 보려면 같은 공유 연결을 사용해야 합니다.
