SANDS Lunch Club | Slackbot 이메일 직접 알림 (추천 · Slack 관리자 불필요)
=========================================================================

[작동 방식]
SANDS Lunch Club 점심 초대 또는 모임 참여 요청 발생
-> 기존 Google Apps Script가 공식 MailApp으로 이메일 1건 발송
-> 수신자의 개인 Slackbot '이메일 전달 주소'로 도착
-> 수신자의 Slackbot 대화에서 점심 알림 확인
-> 링크를 눌러 Lunch Club 웹사이트에서 실제 수락/승인

* 이 방법은 Slack 앱을 직접 설치하거나 API 토큰을 발급할 필요가 없습니다.
* 모든 Slack 요금제에서 제공되는 기본 기능이나, 회사 조직에서 수신 이메일을
  비활성화했을 수 있으므로 먼저 한 명에게 테스트해야 합니다.
* Google Drive에 알림용 파일이 쌓이지 않고, 소유자 본인도 알림 받을 수 있습니다.
* 다만 이것은 Slackbot에 도착하는 '이메일 전달 메시지'입니다.
  점심판 앱에서 직접 보낸 공식 Slack Bot 채팅 메시지와는 다릅니다.

[1. 직원마다 개인 Slackbot 전달 주소 발급]
Slack 데스크톱에서 본인 계정으로 다음을 실행합니다.
프로필 사진 > 환경설정(Preferences) > 메시지 및 미디어(Messages & media)
> Slack으로 이메일 가져오기(Bring emails into Slack)
> 전달 주소 가져오기(Get a Forwarding Address) > 복사(Copy)

* 이 이메일 주소는 각 직원에게 개별 발급됩니다. 실제 주소를 다른 직원과 혼동하지 마세요.
* 전달 주소를 알면 그 사람의 Slackbot에게 메일을 보낼 수 있으므로 암호처럼 취급합니다.
* 슬랙 메시지나 공개 GitHub, setup.html, 사내 공개 문서에 주소를 기입하지 마세요.
* 수신자가 이 기능을 못 찾으면 회사에서 수신 이메일 기능을 끄거나 숨긴 것일 수 있습니다.

[2. 기존 Google Apps Script 프로젝트에 직원별 주소 등록]
기존 점심판과 연결된 동일 Google Apps Script 프로젝트 > 프로젝트 설정(톱니)
> 스크립트 속성 > 스크립트 속성 추가.

속성 이름: LUNCH_SLACKBOT_FORWARD_EMAILS
속성 값: 다음 JSON의 직원별 빈 문자열(" ")을 실제 전달 주소로 채워 저장합니다.
빈 항목은 그대로 두어도 됩니다. 해당 직원에게는 웹앱 내부 알림이 표시됩니다.

{
  "seongjun": "",
  "juri": "",
  "hyunsu": "",
  "yunchul": "",
  "jingi": "",
  "minjun": "",
  "seongeun": "",
  "yunseok": "",
  "jiwoo": "",
  "hyunju": ""
}

[직원 내부 ID 대응표]
seongjun     = 조성준
juri         = 손주리
hyunsu       = 윤현수
yunchul      = 김윤철
jingi        = 천진기
minjun       = 최민준
seongeun     = 오성은
yunseok      = 장윤석
jiwoo        = 서지우
hyunju       = 조현주

[3. 한 명에게 시험 발송]
예를 들어 손주리에게 테스트하려면:
속성 이름: LUNCH_SLACKBOT_TEST_MEMBER
속성 값: juri

Google Apps Script 편집기로 돌아가서 상단 함수 선택 드롭다운에서
  testLunchSlackbotForwarding
를 선택한 뒤 [실행]합니다.
처음 실행할 때 '메일 보내기' 권한이 표시되면 본인 계정으로 허용합니다.
(Google Workspace 정책 때문에 승인되지 않으면 관리자에게 확인하세요.)

실행 로그에 'Slackbot 전달 주소로 이메일을 보냈습니다'가 나와도
실제 Slack 메시지가 도착했는지는 수신자 Slackbot 대화에서 확인해야 합니다.
일부 회사는 허용된 발신자/도메인만 Slack으로 들어오도록 제한합니다.

[4. 기존 사이트 업데이트]
1) 이번 ZIP을 압축 해제한 뒤 내부 파일 전체를 GitHub lunch-club 저장소에 업로드
2) 업데이트된 https://jsj-sands.github.io/lunch-club/setup.html#update 를
   기존 팀 공유 연결이 저장된 브라우저에서 열기
3) '공유 서버 코드 전체 복사'를 눌러 기존 Google Apps Script Code.gs 전체 교체
4) 배포 > 배포 관리 > 기존 웹 앱 수정(연필) > 새 버전 > 배포
5) 'testLunchSlackbotForwarding' 실행으로 수신 확인

처음 설정했던 팀 키, 기존 웹 앱 /exec URL, 모든 날짜별 점심 기록을 유지하세요.
Slackbot 주소는 서버 속성에만 있고 공개 소스 코드/직원 화면으로 전달되지 않습니다.

[알림 이벤트]
- 동료 여러 명 초대 -> 수신자 각각
- 다른 모임에 참여 요청 -> 그 모임 최초 생성자
- 초대 수락/거절 -> 초대한 사람
- 모임 참여 요청 승인/거절 -> 요청한 사람
- 모임 참여 요청 취소 -> 모임 생성자

[설정 우선순위]
1순위: LUNCH_SLACKBOT_FORWARD_EMAILS의 해당 직원 이메일 (추천)
2순위: Google Drive 새 파일 공유 방식 (별도 설정이 있을 때)
3순위: 기존 Slack API Bot DM (해당 설정이 있을 때)
1순위가 성공하면 2,3순위의 중복 발송은 하지 않습니다.
모든 외부 알림에 실패해도 점심판 내부 알림과 모임 기록은 유지됩니다.

[주의]
- Slack 조직에서 수신 이메일 기능이 꺼져 있으면 관리자의 승인이 필요할 수 있습니다.
- 메일 수신 지연, Google MailApp 전송 한도, Slack 필터링 등의 영향이 있습니다.
- 알림 실패 시 자동 재시도하지 않습니다. 중요한 요청은 웹앱에서도 확인하세요.
- 앱에서 선택하는 직원 이름은 강력한 사용자 인증이 아닙니다.
- Slack 전달 주소는 공개 GitHub 파일이나 README에 저장하지 마세요.
- 발송 기록은 Apps Script 로그에 남지만 Slack 수신 여부를 서버에서 조회할 수는 없습니다.
