이번 수정 · 강남밥상 Threads 게시물 점심판 안에서 자동 보기

일반 점심은 메가존 / 런치타임 / 강남밥상 중 한 곳만 개인별로 고릅니다. 대표님과 점심인 사람은 과천 맛집 골라보기 → 대표님 점심 장소을 누르면 그날 모든 대표님 점심 참석자가 동일한 식당을 확인할 수 있습니다. 따로 먹기는 동료를 여러 명 한꺼번에 초대하고 모임별로 과천 맛집 식당을 등록할 수 있습니다. 식당 예약은 별도로 진행합니다.

간편식·데일리팩·테이크아웃을 제외하고 메가존 일반식 메뉴 1·메뉴 2만 표시합니다. 오늘과 주간 요약·상세에 모두 적용되며 날짜가 바뀌어도 계속 유지됩니다. 일반식 사진과 반찬 목록은 그대로 볼 수 있습니다.

메가존은 메뉴별 음식 사진과 밥·국·반찬 목록까지 보여 줍니다. 사진을 누르면 확대할 수 있고, 이번 주 식단은 날짜별 사진·반찬 보기를 펼치면 됩니다. 사진이 없는 날에도 메뉴명은 표시됩니다.

런치타임의 식단 이미지 직접 올리기·교체·삭제 UI를 제거했습니다. 카카오 자동 식단 조회·사진 확대·원문 링크·다시 불러오기는 유지합니다. 과거 업로드된 파일은 삭제하지 않고 화면에서만 숨깁니다.

회사 CI 심벌과 공식 워드마크를 적용했습니다. 사이트 전체의 한글은 Pretendard, 영문·숫자는 Red Hat Display로 표시됩니다. 두 글꼴 파일을 함께 포함했습니다. 배경은 로고 시스템 자료의 미색 #F7F5F0이며 주요 버튼과 강조 요소는 회사 레드입니다. 식당 분류는 스마트경양식 → 양식 / 샤브올데이 → 아시안 / 상월 → 일식으로 보정했습니다.

카카오 프로필 사진을 매일 저장하지 않아도 런치타임 식단을 볼 수 있어요. 공유 서버 연결 후 점심판을 열면 자동으로 가져오고, 화면이 열려 있는 동안 약 5분마다 다시 확인합니다. 사진을 누르면 크게 볼 수 있습니다.

확인 시각은 식단 날짜가 아닙니다. 사진에 적힌 날짜를 확인해 주세요. 내일·모레 화면에는 현재 프로필 사진을 그날 식단으로 표시하지 않습니다. 조회 실패 시 이전 사진·원문 링크·사진 다시 불러오기를 사용할 수 있어요.

함께 먹기 · 따로 먹기 · 안 먹기를 화면에서 바로 선택합니다. 함께 점심 / 대표님과 점심 / 오늘 안 먹음 / 미선택 네 그룹과 따로 먹는 모임을 확인할 수 있습니다.

  • 직접 함께 먹기를 선택한 사람만 초록색 그룹에 들어갑니다. 대표님 기본 일정 외에는 미선택으로 시작합니다.
  • 내 대표님 점심 취소 버튼과 대표님 점심 전체 취소 체크를 보이게 배치했습니다. 취소 후에는 미선택으로 이동합니다.
  • 불참 사유에 연차·반차·외근·출장을 하나의 항목으로 추가했습니다.
  • 따로 먹기에서 동료를 초대하고 각 동료가 수락하면 여러 명의 한 모임으로 표시합니다. 모임별 식당도 따로 등록합니다.
  • 런치타임 아래에 주변 식당을 한식·중식·일식·양식·분식·아시안으로 정리했습니다.
  • 한 번에 하루만 표시하고 ← / →로 날짜를 바꿉니다. 팀명과 이름은 가나다순입니다.
이번 강남밥상 추가에는 GitHub의 index.html, styles.css, app.js, core.js, threads-menu-source.js, setup.html을 교체하고 공유 서버도 업데이트해야 합니다. 기존 Slack/Drive 알림 속성은 유지하세요. 다만 세 번째 장소의 팀 공유 저장을 위해 같은 Apps Script 프로젝트의 서버 코드는 새 버전으로 배포해야 합니다. 메뉴표 자동 조회 기능을 적용하려면 기존 Apps Script 코드도 새 버전으로 업데이트해야 합니다.

1. GitHub 파일 교체

  1. 이번 ZIP을 압축 해제합니다. 기존 lunch-club 저장소에서 Add file → Upload files를 누릅니다.
  2. 기존 저장소의 index.html, styles.css, app.js, core.js, threads-menu-source.js, setup.html 여섯 파일을 같은 경로로 업로드하고 Commit changes로 저장합니다.
  3. GitHub Pages 업데이트 후 사이트를 강력 새로고침합니다. 그다음 기존 Google Apps Script 서버도 새 버전으로 업데이트합니다.

2. 기존 Google 공유 서버 업데이트 · 강남밥상 자동 메뉴 기능 포함

강남밥상 자동 조회: 우선 RSSHub 공개 Threads 피드를 서버에서 확인하므로 별도의 Threads API 토큰 없이도 시도할 수 있습니다. 다만 RSSHub는 Meta 공식 서비스가 아닌 공개 커뮤니티 서비스여서 언제든 막히거나 지연될 수 있고, 강남밥상 실계정 조회도 아직 검증되지 않았습니다. 같은 날 음식 영상과 메뉴 공지 영상을 설명으로 구분하지 못하면 메뉴라고 추측하지 않고 게시물들을 이 화면에서 보여줍니다. LUNCH_THREADS_ACCESS_TOKEN은 공식 API 접근 권한을 이미 확보한 경우의 선택적 예비 수단입니다. 기존 Slack/Drive 스크립트 속성은 유지하세요.

기존 팀 공유를 이미 설정했고 알림도 정상 동작한다면 이번 변경에서도 서버 코드를 새 버전으로 교체하세요. 기존 팀 키와 /exec 공유 주소도 그대로 유지합니다.

  1. 평소 팀 공유에 연결해 쓰던 브라우저에서 https://jsj-sands.github.io/lunch-club/setup.html#update를 엽니다. 강력 새로고침 후 위 제목이 ‘이번 수정 · 강남밥상 Threads 게시물 점심판 안에서 자동 보기’인지 확인합니다. Windows: Ctrl+Shift+R / Mac: ⌘+Shift+R.
  2. 아래 공유 서버 코드 전체 복사를 누릅니다. 이 브라우저에 저장된 기존 팀 키가 코드에 들어갑니다. 다른 브라우저라면 ‘다른 브라우저에서 설정했거나 기존 팀 키가 있어요’를 열고 기존 키를 입력한 뒤 복사합니다.
  3. Google Apps Script의 기존 SANDS 점심판 프로젝트를 엽니다. Code.gs 전체를 복사한 새 코드로 교체하고 저장합니다. 이미 공유·이미지 연결을 완료했다면 초기 실행은 필요하지 않습니다.
  4. 배포 → 배포 관리 → 현재 웹 앱 선택 → 수정(연필) → 버전: 새 버전 → 배포로 갱신합니다.
  5. 기존 점심판을 새로고침해 팀 공유 연결됨을 확인합니다. 대표님 점심 참석자 이름으로 과천 맛집을 고른 뒤 우측 대표님 점심 장소에 확정된 식당이 표시되는지 확인해 주세요. 다른 기기에서도 동일한 장소가 표시되어야 합니다. 추가로 3명 이상 따로 먹는 모임을 만들고 모임별 식당이 다른 기기에도 보이는지 확인합니다. 기존 카카오 사진·메가존 사진·반찬도 계속 사용할 수 있습니다.

같은 프로젝트·팀 키·기존 배포를 갱신하면 공유 주소와 초대 링크, 저장된 개인 선택·일정 설정·공용 이미지를 이어서 쓸 수 있습니다. 코드가 들어 있는 ZIP 원본은 팀 키가 비어 있으므로 위 복사 버튼으로 만든 코드를 사용하세요.

슬랙 관리자가 아니어도 가능합니다. 각 동료가 Slack에서 본인만의 개인 Slackbot 이메일 전달 주소를 발급받아 점심판 관리자에게 전달하면, Google Apps Script가 초대·참여 요청에 맞춰 자동 이메일을 보내고 Slackbot에서 알림을 받을 수 있습니다. 전송용 Google Drive 파일도 만들지 않습니다. 회사 정책에 따라 기능이 막혀 있다면 아래 Google Drive 방식으로 시험할 수 있습니다.

1

직원 본인이 Slack 전달 주소 복사

Slack에서 프로필 사진 → 환경설정 → 메시지 및 미디어 → Slack으로 이메일 가져오기 → 전달 주소 가져오기를 선택합니다. 모든 요금제에서 사용할 수 있지만 회사가 수신 이메일을 비활성화했을 경우엔 사용할 수 없습니다.

2

Google Apps Script의 비공개 설정에 주소 등록

기존 점심판 Apps Script 프로젝트의 프로젝트 설정 → 스크립트 속성에 LUNCH_SLACKBOT_FORWARD_EMAILS를 추가합니다. 값은 {"juri":"손주리_개인_Slackbot_전달주소"} 같이 직원별 내부 ID와 실제 전달 주소를 연결한 JSON입니다. 예시를 그대로 사용하지 말고 ZIP의 Slackbot_이메일_알림_설정_안내.txt를 확인하세요. 이 주소를 GitHub나 사이트 공개 코드에 넣지 마세요.

3

한 명에게 수동 시험 발송

LUNCH_SLACKBOT_TEST_MEMBER 속성에 juri처럼 시험할 직원의 ID를 저장하고, Apps Script 함수 드롭다운에서 testLunchSlackbotForwarding을 실행합니다. 처음에는 Google 메일 발송 권한 승인이 필요할 수 있습니다. 실행 로그가 성공이어도 수신 직원의 Slackbot 대화에서 실제 메시지 도착을 반드시 확인하세요.

이메일 알림은 점심판 내부 알림을 대체하지 않습니다. 수신자가 클릭해서 승인하거나 수락해야 하는 실제 동작은 웹사이트에서 수행됩니다. 모든 외부 알림은 옵션이고, 실패하더라도 초대·참여 요청 기록을 취소하지 않습니다.

Google Drive 공유로 Slack 알림 받기 (선택 · Slack 관리자 불필요)

회사의 Slack에 이미 Google Drive 앱이 연결되어 있다면 새 파일을 나에게 공유한 알림을 Slack에서 받을 수 있습니다. 이번 버전은 동료 초대·모임 참여 요청·수락·승인 같은 이벤트마다 자동으로 작은 텍스트 파일을 만들어 해당 직원의 Google 계정에 보기 권한으로 공유합니다. Google Drive 공유 알림이 Slack에서 뜨는지는 직원별 알림 설정에 따라 달라지므로 먼저 한 명에게 테스트해야 합니다.

1

직원 Google 계정 이메일 등록

기존 Apps Script 프로젝트에서 프로젝트 설정 → 스크립트 속성에 LUNCH_DRIVE_MEMBER_EMAILS를 추가합니다. 예: {"juri":"실제_동료의_이메일@example.com"}처럼 직원 내부 ID를 실제 Google 이메일에 대응시킨 JSON입니다. 예시를 그대로 사용하지 말고, 안내 파일의 빈 양식에 실제 이메일을 입력해 주세요. 사내 도메인 제한은 선택적으로 LUNCH_DRIVE_ALLOWED_DOMAIN을 설정합니다.

2

테스트할 동료 지정 후 알림 발송

같은 스크립트 속성에 LUNCH_DRIVE_TEST_MEMBER를 추가하고 값으로 juri처럼 테스트 대상 직원의 ID를 입력합니다. Apps Script 상단 함수 선택에서 testLunchDriveNotification을 선택하고 실행하면, 해당 직원에게 알림 파일을 새로 공유합니다. Google 권한 요청이 뜨면 허용하고 직원이 Slack의 Google Drive 앱 알림을 실제로 받았는지 확인합니다.

3

다른 직원 이메일 확장

테스트에 성공한 뒤 다른 직원도 JSON에 등록합니다. 등록하지 않은 직원은 웹앱의 초대/참여 요청 알림만 받습니다. 공유된 파일은 전용 비공개 Drive 폴더에서 14일 보관한 뒤 정리합니다. 직원의 실제 이메일을 GitHub에 올리지 마세요.

주의: Apps Script의 실행 계정 자신에게는 자기 소유 파일을 새로 공유할 수 없어서, 해당 직원은 이 방식의 Slack Drive 알림을 받지 못합니다. 또한 Slack 일반 DM을 보내는 것이 아니라 Google Drive 앱에서 파일 공유를 알려 주는 것입니다. 기존 웹앱 알림은 모든 직원에게 계속 표시됩니다.

상세한 직원별 이메일 JSON 양식과 예외 처리, 테스트 방법은 ZIP의 Google_Drive_Slack_알림_설정_안내.txt를 확인하세요. 공유 서버 코드는 위 공유 서버 코드 전체 복사 버튼으로 기존 팀 키를 유지해 업데이트해야 합니다.

Slack DM 알림 설정 (선택)

회사에서 Slack 앱 생성 권한을 받을 수 있다면 Google Drive 방식 대신 직접 Slack DM을 보낼 수도 있습니다. 설정하지 않아도 앱 안의 알림과 수락·승인 기능은 정상 작동합니다. Slack DM은 앱에 로그인을 요구하지 않으며 수락·승인은 웹사이트에서 진행합니다.

1

Slack 앱 만들기

Slack 관리자에게 앱 설치 가능 여부를 확인합니다. Slack API → Create an App에서 SANDS Lunch Club 봇을 만들고 OAuth & Permissions의 Bot Token Scopes에 chat:write와 im:write를 추가한 뒤 워크스페이스에 설치합니다.

2

사람별 Slack ID 수집

각 동료의 Slack 프로필 메뉴에서 멤버 ID 복사를 눌러 U... 또는 W... ID를 수집합니다. 부서·실명만으로 DM 대상을 자동 추측하지 않습니다.

3

Apps Script에 비밀값 저장

기존 Apps Script의 프로젝트 설정 → 스크립트 속성에 LUNCH_SLACK_BOT_TOKEN (Slack Bot User OAuth Token, xoxb-...)과 LUNCH_SLACK_MEMBER_IDS (직원 ID와 Slack ID를 연결한 JSON 문자열)를 추가합니다. 구체적인 10명 ID 양식은 ZIP의 Slack_알림_설정_안내.txt를 보세요. GitHub·setup.html에 토큰을 넣지 마세요.

4

새 버전 배포 후 테스트

같은 Apps Script 프로젝트에서 이 페이지의 새 Code.gs로 교체 후 배포 관리 → 기존 웹 앱 편집 → 새 버전 → 배포하고 실제 직원에게 초대/참여 요청을 보내 확인합니다. DM이 오지 않아도 사이트는 약 30초마다 공유 상태를 갱신합니다. Slack 연결 문제는 Apps Script 실행 로그를 확인하세요.

신원 확인 주의: 이 앱은 이름 선택·팀 키 방식이며 Slack 계정 로그인과 묶여 있지 않습니다. 이름 변경으로 다른 직원 대신 버튼을 누를 수 있으므로 사내 구성원만 공유 링크를 사용해 주세요. Slack 전송 실패는 점심 기록을 취소하지 않으며 자동 재발송하지 않습니다.

매일은 이렇게 사용해요

  1. 오늘 점심, 어떻게 할까요?에서 나는 → 내 이름을 선택합니다. 팀명과 이름은 가나다순으로 표시됩니다.
  2. 큰 버튼 함께 먹기 · 따로 먹기 · 안 먹기 중에서 선택합니다. 아무것도 선택하지 않으면 미선택입니다. 함께 먹기를 선택해야 초록색 그룹과 식당 투표 집계에 포함됩니다.
  3. 안 먹는 날에는 필요한 경우 사유를 선택합니다. 연차·반차·외근·출장은 하나의 항목입니다.
  4. 자동으로 들어간 대표님 일정이 취소됐다면 내 대표님 점심 취소를 누르고 점심 여부를 다시 고릅니다. 그날 전체 일정이 취소됐을 때에는 대표님 점심 전체 취소를 체크합니다.
  5. 동료끼리 따로 먹는 날은 따로 먹기 → 동료 여러 명 체크 → 초대를 누릅니다. 초대받은 동료가 본인 이름을 선택하고 수락하고 따로 먹기를 누르면 같은 모임으로 표시됩니다. 다른 직원은 모임 카드의 이 모임에 참여 요청을 눌러 먼저 제안할 수 있고 생성자가 승인하면 합류합니다. 혼자 먹을 때는 동료 지정 없이 따로 먹기를 선택합니다.
  6. ← / →로 내일·모레 현황과 선택을 확인하고 오늘 버튼으로 돌아옵니다. 선택과 초대는 화면에 표시된 날짜에만 저장됩니다.
  7. 메가존의 오늘 식단 / 이번 주 식단을 비교합니다. 런치타임은 자동으로 가져온 카카오 프로필 사진을 확인합니다. 사진에 적힌 식단 날짜를 확인해 주세요. 필요한 경우 식단 이미지 직접 올리기로 주간용·하루용 이미지를 따로 공유할 수 있습니다.
  8. 일반 점심에 참여하면 응답 패널 또는 메가존/런치타임 식단 카드에서 둘 중 하나를 고릅니다. 바꾸고 싶으면 다른 한 곳을 누르면 됩니다. 각자의 선택이 집계됩니다.
  9. 대표님과 점심인 사람은 아래 과천 맛집 골라보기에서 종류·이름으로 찾아 대표님 점심 장소를 누릅니다. 우측에 팀 전체가 보는 등록 장소가 표시됩니다. 변경하려면 다른 식당을 고르고 확인합니다.
  10. 대표님 점심의 기본 만남 시간은 설정에 있는 시간(기본 12:00)을 사용합니다. 일반 점심에는 따로 전체 장소 확정 단계가 없고 각자 선택으로 끝납니다.
대표님과 점심·안 먹음·미선택·따로 먹기는 함께 먹는 인원과 식당 투표 집계에서 빠집니다. 기존 식당 선택은 보관되며, 다시 함께 먹기를 선택하면 집계에 돌아옵니다. 초대나 참여 요청만 보냈을 때는 상대의 점심 상태가 바뀌지 않습니다. 수락 또는 승인 시에는 자동으로 일반 함께 점심 인원에서 빠집니다.

식단과 일정에 대해 알아둘 점

  • 메가존: 공유 연결 전에도 공개된 날짜별 점심 메뉴를 직접 조회합니다. 오늘과 이번 주 월~금 식단을 볼 수 있습니다. 날짜가 맞는 식단만 표시하며, 미등록과 조회 실패를 구분합니다. 메뉴 사진과 상세 내용은 Welplan 원문에서 확인합니다.
  • 런치타임 자동 조회: 공유 서버가 카카오 채널에 공개된 최신 프로필 사진 주소를 가져옵니다. 별도 카카오 로그인이나 친구 추가가 필요하지 않습니다. 점심판을 열 때와 화면이 열려 있는 동안 약 5분마다 확인합니다. 채널에 아직 전날 사진이 있으면 그 사진이 표시되므로 이미지 속 날짜를 확인해 주세요. 페이지를 닫은 상태의 오전 9시 예약 실행은 이번 버전에 포함하지 않습니다. 공개 화면의 데이터 형식이 바뀌면 자동 조회 코드 조정이 필요할 수 있습니다.
  • 직접 올린 식단 이미지 기간: 주간용은 월~일, 하루용은 지정한 날짜에 표시합니다. 같은 날짜에 하루용과 주간용이 모두 있으면 하루용을 우선 표시합니다. 다음 주에는 지난 주 이미지가 표시되지 않습니다.
  • 이미지 공유: 원본 선택은 15MB까지 가능하며 업로드 전 크기를 조정합니다. 이미지는 전용 비공개 Drive 폴더에 저장하고 팀 키로 조회합니다. 이미지 자체를 인터넷 공개 링크로 만들지 않습니다. 공유 연결 전 미리보기는 이 브라우저에만 보관하며 공유 연결 후 다시 올려야 합니다.
  • 대표님과 점심 기본 일정: 경영지원팀 김윤철·오성은·장윤석 수 / 디자인팀 서지우·천진기 화 / 연구기획팀 최민준 월·목 / 영업팀 조현주 월·금 / 전략사업팀 손주리·윤현수 월·화·금 / 커뮤니케이션팀 조성준 화·금. 연구기획팀은 연구소 팀장 일정을 따릅니다. 첨부 공지를 반영해 2026년 12월 31일까지 적용하며, 설정에서 기간과 요일을 바꿀 수 있습니다.
  • 주말·공휴일: 주말도 기본 미선택입니다. 공휴일은 자동 판정하지 않으므로 필요한 경우 대표님 일정을 취소하고 각자 점심 여부를 선택해 주세요.
  • 과천 맛집: 주변 식당 지도의 가게를 2026년 10월 19일 확인해 정리했습니다. 한식·중식·일식·양식·분식·아시안으로 나누고 스마트경양식·샤브올데이·상월은 요청에 맞게 분류를 보정했습니다. 원본 지도에 이후 추가한 장소는 이 파일에 자동 반영되지 않습니다. 맛집 목록은 대표님 점심 장소와 따로 먹는 모임별 식당 등록에 사용합니다. 일반 점심은 계속 메가존/런치타임 중 하나만 선택합니다.
  • 따로 먹는 모임: 동료 여러 명을 동시에 초대하여 모임을 만들고, 참여자는 모임 식당을 등록할 수 있습니다. 대기 중인 초대를 포함해 한 사람은 한 모임에만 들어갈 수 있습니다. 초대를 거절·취소하면 초대한 사람은 따로 먹기로 남고, 수락한 모임에서 나가면 본인만 미선택으로 바뀝니다.
  • 기록 보관: 공유 기록과 전용 식단 이미지는 최근 90일을 기준으로 정리합니다. 이 기기의 점심 기록은 최근 120일 보관합니다. 예전에 올린 이미지 데이터는 새 화면에서 표시하지 않습니다.

잘 안 될 때

상황확인할 것
GitHub 주소가 404예요저장소 첫 화면에 index.html이 있는지, Pages가 main / (root)인지 확인합니다.
공유 서버 업데이트 안내가 떠요맨 위 기존 서버 업데이트 순서대로 Code.gs를 교체하고 배포 관리에서 새 버전으로 갱신합니다. GitHub 파일 교체만으로는 이번 다인원 초대와 따로 먹기 식당을 팀에 저장할 수 없습니다.
동료와 선택이 달라요양쪽 모두 ‘팀 공유 연결됨’인지 확인합니다. 일반 주소 대신 ‘동료 초대’로 복사한 링크를 전달하세요.
팀 키 오류예요코드를 복사했던 브라우저에서 다시 연결합니다. 새 코드를 넣었다면 새 버전으로 재배포해야 합니다.
연결 응답이 없어요웹 앱 실행 사용자 ‘나’, 접근 권한 ‘모든 사용자’, 주소 끝 /exec를 확인합니다. Workspace에서 익명 배포가 금지되어 있으면 관리자 확인이 필요합니다.
식단이 안 떠요원문 서비스 또는 네트워크 문제일 수 있습니다. 메가존은 ‘식단 새로고침’과 Welplan 원문, 런치타임은 ‘사진 다시 불러오기’와 카카오 원문을 확인합니다. 런치타임 자동 조회의 서버 업데이트 안내가 있을 때만 기존 서버 버전을 확인합니다. 이전 사진은 마지막 확인 시각과 오류 안내를 함께 표시합니다.
강남밥상 게시물이 표시되지 않아요RSSHub 공개 피드가 접속 가능한지 확인하세요. 기본 서버는 두 공개 피드를 순서대로 조회하며 실패할 수 있습니다. 영상을 확인할 수 있다면 재생·정지로 메뉴표 장면을 찾을 수 있습니다. 같은 날 영상이 여럿 올라와 자동 구분이 어렵다면 게시물들을 점심판 안에 나누어 표시합니다. 이미 Threads 공식 API 권한이 있는 경우 비공개 스크립트 속성 LUNCH_THREADS_ACCESS_TOKEN을 예비 수단으로 사용할 수 있습니다.
런치타임 식단 직접 올리기 버튼이 없어요정상입니다. 이번 버전부터 직접 업로드·교체·삭제 UI를 제거하고 카카오 자동 식단만 사용합니다.
공유 서버 코드를 수정했어요배포 → 배포 관리 → 수정(연필) → 버전 ‘새 버전’ → 배포. 기존 주소를 유지하면 팀 연결을 바꿀 필요가 없습니다.
